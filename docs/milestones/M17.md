# M17: Gizmos and undo

## What was built

The two things that make editing comfortable: handles to drag objects into place, and a way back
from every mistake.

- **Gizmos:** handles drawn on the selected object, like Unity's Scene view tools.
  - **Move (W):** an arrow per axis, plus small squares that move along two axes at once.
  - **Rotate (E):** a ring around each axis. The half facing the camera is solid and can be
    grabbed; the back half is faint.
  - **Scale (R):** a box at the end of each axis, plus a box in the center that scales evenly.
  - **Local / Global (X):** the handles follow the object's own axes or the world's. Scale always
    uses the object's own axes, as in Unity.
  - **Snapping:** hold **Ctrl** while dragging. Moves go in steps of 1 unit, turns in steps of 15°.
  - A **toolbar** above the Scene view has the same switches as buttons.
  - The handles stay the same size on screen at any distance, and turn yellow under the mouse.
- **Undo and Redo** (Ctrl+Z, Ctrl+Y, and in the Edit menu) cover every edit: creating, deleting,
  duplicating, renaming, reparenting, adding and removing components, every Inspector field, and
  gizmo drags. One drag (of a value or of a handle) is one step, and so is one name typed. Undo
  also brings back the selection, and undoing back to the saved state clears the `*` in the title.
- **Engine additions:**
  - **`GameObject::GetId()`:** a number that identifies an object in its scene, like Unity's
    `GetInstanceID`, plus **`Scene::FindById`**.
  - **`Scene::Serialize(withIds)` / `Deserialize`:** the scene as JSON in memory. `Save` and
    `Load` are now these plus the file. M18's Play mode will use them too.
  - **`Transform::SetPosition` / `SetRotation`:** setters in world space, like Unity's
    `position` and `rotation` setters.

## Concepts

### Undo with snapshots (the memento pattern)

There are two classic ways to build undo:

1. **Commands:** every edit is an object that knows how to apply itself and how to reverse itself.
   "Delete Cube" remembers the cube so it can put it back; "Set Position" remembers the old value.
   That's what Unity's `Undo` records, and it's memory-efficient. But every kind of edit needs its
   own reversing code, and getting all of them right is a lot of work.
2. **Snapshots (mementos):** after every edit, write down the whole state. Undo means "put back the
   state before". The reversing code is the same for every edit: load the snapshot.

The engine can already write a whole scene down: M13's scene files. So `SceneEditor` (M16's single
place for every edit) uses snapshots. It writes the scene to JSON text in memory with
`Scene::Serialize`, and restores it with `Scene::Clear` and `Scene::Deserialize`, just as a scene
file loads. A snapshot of a small scene is a few kilobytes, about half a kilobyte per GameObject.
The history keeps the last 100. The objects' meshes, textures and materials are still loaded when a
snapshot comes back, so an undo is quick.

The history is two stacks around the current state:

- **Undo** pushes the current state onto the redo stack and puts back the top of the undo stack.
- **Redo** does the reverse.
- **A new edit** clears the redo stack: once you change the past, the undone future is gone, as in
  every editor.

Each state also carries a step number. The `*` in the title means "the current step isn't the one
that was saved", so undoing back to the saved state makes it clean again.

### When is an edit finished?

Dragging a value in the Inspector changes it every frame. Taking a snapshot every frame would make
undo go back one frame of the drag at a time. Unity groups the whole drag into one undo step, and
so does this editor. The rule is simple:

- Any change says `MarkChanged()`: an edit is in progress.
- At the end of each frame, `EndFrame` checks whether the user is still holding something:
  `ImGui::IsAnyItemActive()`, a widget being dragged, a text field being typed in, a gizmo handle
  held.
- Once nothing is held any more, the edit is finished, and the snapshot is taken.

That one rule covers Inspector drags, text fields, checkboxes, combo boxes, Hierarchy drops and
gizmo drags alike. For the gizmo to fit in, the Scene view's image became an ImGui **item**: an
`InvisibleButton` with the picture drawn on it. ImGui then knows when a press on it starts
(`IsItemActivated`), lasts (`IsItemActive`) and ends. That was one of M15's deferred items.

A snapshot that comes out identical to the previous one (a value dragged back to where it was) isn't
kept as a step. A click on a handle that doesn't move it changes nothing at all.

### Ids: which object was selected?

Restoring a snapshot creates **new** GameObjects at new addresses, so a pointer to the selected
object is useless afterwards. Every GameObject now has an **Id**: a number the scene hands out when
the object is created, never reused (Unity's instance ID). Undo snapshots include the Ids
(`Serialize(true)`), and `Deserialize` gives each object its Id back, so:

- the selection is stored as an Id and found again with `Scene::FindById`;
- the Hierarchy uses the Id as each line's ImGui ID (instead of the address, as in M16), so open
  branches stay open across undo.

Scene files leave the Ids out. They describe a scene, not one session's objects, and objects loaded
from a file get fresh Ids. `Instantiate` (Duplicate) gives the copy fresh Ids too.

### Gizmos: everything happens on screen

A gizmo is drawn the same way as M16's selection outline: with ImGui's draw list, over the image,
after projecting 3D points onto the screen (`SceneViewport::ToScreen`). Each frame:

1. **`MakeFrame`:** the gizmo's center (the object's world position, and where it shows on screen)
   and its three axes. With Local, those are the object's rotation applied to X, Y and Z. They also
   get a **size in the world that is 100 pixels on screen** at the object's distance
   (`PixelsToWorld`), which keeps the handles the same size near and far.
2. **`Project`:** every handle as it appears on screen: the axis tips, the plane squares' corners,
   and the rings as 64 short segments each. Hit-testing and drawing both use this one result, so
   what's grabbed is exactly what's seen.
3. **`HitTest`:** which handle is under the mouse, measured in pixels. That's how far the mouse is
   from a line segment, or whether it's inside a square.
4. **`Draw`**, with the handle under the mouse (or being dragged) in yellow.

On a press over a handle, **`BeginDrag`** remembers where everything started. Each following frame,
**`Drag`** works out the change from that start, rather than adding up small steps, so snapping and
rounding errors don't build up:

- **Move along an axis:** the mouse gives a ray (M16). The object moves to the point on the axis's
  line that is **closest to the ray**: two lines in 3D usually don't meet, but they have one pair of
  closest points, from a short formula (`ClosestAlongAxis`). The object moves by the distance from
  where the drag started along the axis.
- **Move along a plane:** where the ray **meets the plane** (`IntersectPlane`), compared with where it
  met it at the start.
- **Rotate:** at the start, the grabbed point on the ring and the direction it would move if the
  object turned a little. Around axis A, a point at r from the center moves along **A × r** (the
  cross product; the right-hand rule). Projected on screen, that's the direction to drag in. Dragging
  one ring radius along it turns one radian. This works from any viewing angle, even when the ring
  is seen nearly edge-on.
- **Scale:** how far the mouse moved along the axis's line on screen, compared with the handle's
  length. Dragging out to twice the length doubles the scale.

The result goes into the Transform through **`SetPosition`/`SetRotation`**, which work out the local
values through the parent's inverse matrix, so a child object's gizmo works in the world too.

### Keys

The keys now follow one rule. Undo and Redo work wherever you are. The selection's commands (F, F2,
Del, Ctrl+D) and the tools (W, E, R, X) work while the Hierarchy or the Scene view has the focus.
None of them work while something is held: in the middle of a gizmo drag, Ctrl+Z or Del would pull
the object out from under the gizmo. W/E/R don't switch tools while flying with the right mouse
button either, because then W moves the camera. In a text field, Ctrl+Z undoes your typing, as text
fields normally do, because `Input` doesn't see keys while a text field has the keyboard (M9).

Each set of keys lives in one table with its labels, so the key a menu item or a button shows is
always the one that works:
- `EditorMenus.cpp` for the Edit commands;
- `SceneView.cpp` for the tools.

## Reading guide

1. **`editor/src/SceneEditor.h`**, then **`SceneEditor.cpp`**:
   - `MarkChanged`, `EndFrame` and `FinishChange` (when a step ends);
   - `Undo`, `Redo`, `TakeSnapshot` and `Restore`;
   - the edits, each starting with `MarkChanged`.
2. **The engine side of undo:**
   - **`engine/src/Scene/SceneFile.cpp`:** `Serialize` and `Deserialize` (with Ids), and
     `Scene::LoadGameObject`, now a private member so it can give back an Id;

   `Draw`, `BeginDrag`, and `Drag`, case by case. The math helpers sit at the top.

   `RunEditCommand`; **`EditorMenus.cpp`** for the Undo/Redo entries.
7. **`engine/src/Scene/Transform.cpp`:** `SetPosition` and `SetRotation`.

## How to test

1. **Open a project** and select the Cube. Arrows appear on it: red X, green Y, blue Z.
2. **Move:** drag the green arrow up. The cube follows the mouse straight up. Drag the green square
   (between X and Z) to slide it over the ground. Hold **Ctrl** while dragging: it jumps in whole
   units.
3. **Rotate:** press **E**. Drag the green ring: the cube turns around Y. With Ctrl, in steps of 15°.
   Try the rings from different angles, including nearly edge-on.
4. **Scale:** press **R**. Drag an axis box outwards to stretch the cube, or the center box to grow
   it evenly.
5. **Local / Global:** rotate the cube, then press **W** and **X**. The arrows switch between the
   cube's axes and the world's.
6. **Undo:**
   - Ctrl+Z after each of the above puts the cube back, one drag at a time.
   - Ctrl+Y redoes.
   - Delete an object, then Ctrl+Z: it's back, selected.
   - Change a color in the Inspector, then Ctrl+Z.
   - Rename, then Ctrl+Z.
7. **Saved state:** save (Ctrl+S), change something, then Ctrl+Z. The `*` disappears again.
8. **Child objects:** make an object the child of a rotated, scaled parent, and drag it with the
   gizmo. It follows the mouse in the world.

## Known limitations

- **One selection, one pivot:** no multi-select, and the gizmo sits at the object's origin. Unity's
  Center/Pivot switch isn't there.
- **Snapping is relative:** Ctrl moves in whole-unit steps from where the drag started. It doesn't
  snap to the grid lines (Unity calls that grid snapping). There's no scale snapping.
- **Undo history:** 100 steps, kept only while the scene is open. New, Open and Close Project clear
  it. Selection changes aren't undo steps.
- **Snapshots hold the whole scene:** that's fine for hand-made scenes. A scene with thousands of
  objects would make each step slower and bigger. Commands would scale better.
- **Inspector Euler angles** can still jump past ±90° on X (M15).
- **Gizmo drags can't be scripted** (see Verified on).
