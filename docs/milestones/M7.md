# M7: Textures

## What was built

The scene gets textures: a wooden crate spins in the middle, and the floor is a single square
with a repeating checker pattern. The pillars keep their plain colors.

- **Two textures**, drawn by `scripts/make-textures.ps1` (procedural, no third-party art) and
  committed:
  - `assets/textures/crate.png` (256×256);
  - `assets/textures/checker.png` (64×64).
- **stb_image** (Sean Barrett's public-domain single-header library, fetched by CMake like the
  others) decodes PNG and JPEG files. `engine/src/Core/ImageFile.h/.cpp` wraps it:
  `LoadImageFile(path)` returns RGBA pixels.
- **`cmake/Assets.cmake`**: `viva_copy_assets(Sandbox textures/crate.png ...)` copies assets next to
  the executable (`bin/assets/`) and into the packaged build. `GetAssetPath("textures/crate.png")`
  finds them at runtime.
- **`Texture`** (`engine/src/Renderer/Texture.h/.cpp`):
  - an `Image` with a full **mipmap chain**;
  - the pixels arrive through a staging buffer;
  - smaller levels are generated on the GPU with `vkCmdBlitImage`;
  - plus a **sampler**: trilinear, repeating, anisotropic.
- **`TextureDescriptors`**: **descriptor set 1**, one combined image sampler per texture.
- **`Vertex`** gained **UV** texture coordinates (location 2).
- **Shaders:** `shaders/Unlit.vert/.frag` replace the VertexColor shaders. The fragment shader
  multiplies the texture by the vertex color, and a 1×1 white texture leaves the pillars' colors
  as they were.
- **Supporting changes:**
  - `Image` takes a mip level count, and `ImageTransition` a mip range.
  - New descriptor helpers in `VulkanHelpers`, which `FrameUniforms` now uses too.
  - Anisotropic filtering is switched on when the GPU has it.

## Concepts

### Texture coordinates (UVs)

Each vertex now says which point of the texture it shows: its **UV**, from (0, 0) at the
texture's top-left corner to (1, 1) at its bottom-right. Like colors, UVs are interpolated across
each triangle, so every pixel knows where in the texture to look. The cube puts the whole
texture on each face (its corners map to 0 and 1). The floor's UVs run from 0 to 12, and with a
**repeating** sampler the texture tiles 12 times across it, one copy every 2 units. In Unity
that's `Mesh.uv`, plus the material's "Tiling".

Vulkan's UV origin is the image's **top-left**, which is also how image files store their rows,
so nothing needs flipping. OpenGL's is the bottom-left, the reason many OpenGL tutorials flip
images on load.

### Loading an image: PNG to pixels

A PNG is compressed, and the GPU can't read it. `LoadImageFile` reads the file (through
`ReadBinaryFile`, which handles UTF-8 paths on every OS). Then stb_image decodes it into plain
**RGBA**: 4 bytes per pixel, row after row. That's what Unity does when it imports a texture,
except Unity does it once in the editor and stores the result, while we decode at startup.

### From pixels to a GPU texture

1. A staging buffer receives the pixels, as M5's vertex data did.
2. `vkCmdCopyBufferToImage` copies them into **mip level 0** of a `VkImage`. The image uses
   *optimal tiling*, the GPU's own swizzled layout, so it can't be written row by row like a
   buffer.
3. The other mip levels are generated (next section).
4. Every level moves to `SHADER_READ_ONLY_OPTIMAL`, the layout the fragment shader samples from.

### Mipmaps

A **mipmap chain** stores the texture again at half size, quarter size and so on down to 1×1: 9
levels for 256×256. That costs a third more memory.

- **Why:** when a textured surface is far away, many texels land on one pixel. Sampling only one
  of them makes fine patterns shimmer and crawl (aliasing). The GPU instead picks the level whose
  texels are about pixel-sized, which is already averaged.
- **How they're made:** `RecordUploadAndMipmaps` in `Texture.cpp` builds the chain on the GPU.
  Each level is a **blit** (a filtered copy that can resize) of the level above, at half the size.
  Between blits, barriers move one level at a time. That's why `ImageTransition` now has
  `BaseMipLevel` and `MipLevelCount`.
- **What you see:** look at the distant floor. Its 1-pixel lines would flicker without mipmaps;
  with them they fade evenly into gray. Unity's importer has the same "Generate Mip Maps" option,
  on by default.

### Samplers: how a texture is read

A **sampler** is the "how" of reading a texture (Unity's texture import settings):

- **Filtering:** `LINEAR` blends the four nearest texels, so it looks smooth up close (Unity's
  Bilinear). `NEAREST` would look blocky, like pixel art (Unity's Point).
- **Mipmap mode:** `LINEAR` also blends between the two nearest mip levels, so there's no visible
  seam where one level hands over to the next. That's **trilinear** filtering.
- **Address mode:** `REPEAT` wraps UVs past 1, which makes the floor tile. `CLAMP_TO_EDGE` would
  stretch the edge pixels instead (Unity's Wrap Mode).
- **Anisotropic filtering:** extra samples along surfaces seen at a slant, like the floor, keep
  them sharp into the distance (Unity's Aniso Level). It's an optional GPU feature, so
  `VulkanContext` turns it on when present. Every desktop GPU and Apple's support 16×.

### sRGB textures

Image files store **sRGB** values, spaced to suit the eye rather than evenly. Lighting and
blending must happen on **linear** values. The texture's format,
`VK_FORMAT_R8G8B8A8_SRGB`, makes the GPU convert each texel to linear as it's sampled. The sRGB
swapchain (M3) converts back on output. That's the same pipeline as Unity's Linear color space
with "sRGB (Color Texture)" ticked. Textures holding data rather than colors (normal maps,
roughness) would use `_UNORM` and skip the conversion.

### Descriptor set 1: textures

The fragment shader reads `layout(set = 1, binding = 0) uniform sampler2D albedo`. It's a
**combined image sampler**: one descriptor holding both the image view and the sampler.
- `TextureDescriptors` owns set 1's layout and a pool.
- It writes one set per texture.
- Before each object, the renderer binds that object's texture set as set 1. Set 0 (the camera)
  stays bound.

Splitting data by how often it changes (per frame: set 0; per material: set 1; per draw: push
constants) is the usual way to organize descriptors. M8's materials build on it.

### Single-header libraries

stb_image works like VMA: one header that declares the functions everywhere, and defines them in
the one file that sets `STB_IMAGE_IMPLEMENTATION` first (`ImageFile.cpp`). The other defines there
trim it down:
- PNG and JPEG only;
- no file access of its own, since we hand it bytes;
- its internal checks go through `VIVA_ASSERT`.

## Reading guide

1. **`shaders/Unlit.frag`**, then **`shaders/Unlit.vert`**: `sampler2D`, `texture()`, the UV passed
   through.
2. **`engine/src/Renderer/Mesh.h`**: `Vertex::UV` and the third attribute.
3. **`engine/src/Core/ImageFile.cpp`**: the stb defines, decoding from memory, `STBI_rgb_alpha`.
4. **`engine/src/Renderer/Texture.cpp`**:
   - In `Create()`: the mip count (`std::bit_width`), the image's three usages, the staging
     upload, and the sampler settings.
   - Then `RecordUploadAndMipmaps()` from top to bottom: each level's journey from TRANSFER_DST
     to TRANSFER_SRC to SHADER_READ_ONLY.
5. **`engine/src/Renderer/TextureDescriptors.h`** and **`.cpp`**: layout, pool, and `Allocate()`
   writing one combined image sampler.
6. **`engine/src/Renderer/Renderer.cpp`**:
   - `Cube(colorFaces)` and `Floor(size)` with UVs.
   - `DemoScene`: its textures, sets and meshes, and `Draw()` binding a texture per object.
   - The pipeline built with two descriptor set layouts.
7. **`cmake/Assets.cmake`**, **`sandbox/CMakeLists.txt`** and **`GetAssetPath`** in
   `engine/src/Platform/FileSystem.cpp`: how a PNG gets from `assets/` to next to the executable.
8. **`engine/src/Renderer/VulkanHelpers.h`**: the descriptor helpers, and `ImageTransition`'s mip
   range.

## How to test

1. **Run** the Sandbox. A textured crate spins between the pillars, over a checker floor.
2. **Debug log:** "Texture loaded: …crate.png (256x256)" and the checker, then three meshes.
3. **Fly low over the floor** (Q, then W) and look toward the horizon. The floor stays smooth,
   with no shimmering lines, and stays fairly sharp thanks to anisotropic filtering.
4. **Fly close to the crate:** the planks stay smooth up close, thanks to linear filtering.
5. **RenderDoc:**
   - In the *Texture Viewer*, pick the crate texture and step through its mip levels.
   - On a draw, *Pipeline State* shows set 1 with the sampler's settings.
6. **Experiments** (rebuild after each, and revert afterwards):
   - In `Texture.cpp`, set `mipLevels` to 1. The distant floor now shimmers and shows moiré
     patterns as you move.
   - Set `.anisotropyEnable = VK_FALSE`. The far floor turns blurry gray sooner.
   - Set both filters to `VK_FILTER_NEAREST`. The crate looks pixelated up close.
   - Set the address modes to `VK_SAMPLER_ADDRESS_MODE_CLAMP_TO_EDGE`. The floor shows one
     checker tile, then smeared edge pixels.
   - Change `kTextureFormat` to `VK_FORMAT_R8G8B8A8_UNORM`. Everything textured looks washed
     out, because the sRGB values are no longer converted to linear.
   - Edit `assets/textures/crate.png` in any paint program and rebuild. The build copies the new
     file.

## Known limitations

- **Textures are decoded at startup**, synchronously. A shipping engine stores GPU-ready
  (pre-compressed, pre-mipmapped) textures and streams them in. Unity does that work at import.
- **No GPU texture compression** (BC7 and the like). Every texel takes 4 bytes.
- **Fixed descriptor pool:** `TextureDescriptors` has room for 16 textures. M8's materials need a
  growable descriptor allocator.
- **One sampler per texture**, and every texture is treated as an sRGB color texture.
- **Still in the renderer:** the demo scene, including the texture choices, lives there until M8.
- **Uploads wait for the GPU**, one at a time: two waits per mesh, one per texture.
