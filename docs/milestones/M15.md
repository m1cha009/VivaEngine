# M15: Editor shell

## What was built

Opening a project in VivaEditor now opens an **editor that looks like a small Unity**: a menu bar
and five windows, docked into one layout that you can rearrange.

- **Scene:** the scene, seen through the **editor camera**. Hold the right mouse button over it to
  look around, and fly with W/A/S/D/Q/E while you hold it (Shift: faster), as in Unity's Scene view.
  **F** frames the selected object.
- **Hierarchy:** the GameObjects as a tree. Click one to select it; click empty space to deselect.
- **Inspector:** the selected object's Active switch, its Transform, and every component's fields,
  editable: drag a number, pick a color, change a material's color or tiling. Mesh and texture
  names are shown (choosing others comes in M16).
- **Project:** the project's `Assets` and `Scenes` folders. Double-click a `.scene` file to open it.
- **Console:** the engine's log since startup, colored by level, with a checkbox and a count per
  level, and Clear.
- **Menus:**
  - **File:** New Scene (Ctrl+N), Open Scene... (Ctrl+O), Save (Ctrl+S), Save As...
    (Ctrl+Shift+S), Close Project.
  - **Window:** show or hide each window, and Reset Layout.
- **Unsaved changes:**
  - The title bar shows `VivaEditor - Project - Scene*`; the `*` means unsaved changes.
  - New Scene, Open Scene, Close Project and closing the window ask "Save them first?" with
    **Save / Don't Save / Cancel**.
- **Edit mode:** the scene doesn't run while you edit it. Spinners stand still, as scripts do in
  Unity until you press Play (M18).
- **The layout is remembered** between runs, in `%APPDATA%\Viva\VivaEditor\layout.ini`.
- **Engine additions:**
  - **Scene target:** `Renderer::SetSceneTargetSize` and `GetSceneTexture` draw the scene into an
    image of its own, which the UI shows (a render texture).
  - **Application hooks:** `Application::OnRender` (draw from another camera),
    `OnQuitRequested` (ask before quitting) and `SetSceneUpdating` (Edit mode).
  - **`Fly`:** the flying code, shared by `FlyCamera` and the editor camera.
  - **`Log::SetListener`**, which feeds the Console.
  - **`ShowOpenFileDialog`** and **`ShowSaveFileDialog`**, next to `ShowFolderDialog`.
  - **Dear ImGui's docking build**, the same version (`v1.92.9b-docking`), approved for this
    milestone.

## Concepts

### Render to texture

So far the scene was drawn straight into the window's swapchain image, and the UI over it. The
editor needs the scene *inside* a window, as a picture the UI can place anywhere. That's **render
to texture** (Unity: a Camera with a Target Texture, shown on a RawImage):

1. The renderer makes a **scene target**: a color image the size of the Scene window, plus a depth
   buffer of its own. The color image is made with two uses: `COLOR_ATTACHMENT` (drawn into) and
   `SAMPLED` (read by a shader as a texture).
2. Each frame it draws the scene into that image, exactly as it used to draw into the window.
3. A **barrier** moves the image from `COLOR_ATTACHMENT_OPTIMAL` to `SHADER_READ_ONLY_OPTIMAL`. It
   also makes the scene's writes finish, and be visible, before any fragment shader reads them.
4. A second rendering, into the swapchain image, draws only the UI. The Scene window's
   `ImGui::Image` samples the scene target like any texture.
5. Next frame, the first barrier waits for the UI's reads to finish before drawing over the image
   again (a write-after-read hazard).

`Renderer::Impl::RecordRendering` is the one function both renderings use: clear, draw the scene
and/or the UI, end.

ImGui refers to textures by an **ImTextureID**, an opaque 64-bit value. For the Vulkan backend
it's a descriptor set, which `ImGui_ImplVulkan_AddTexture` makes for an image view. The renderer
hands it out as a `uint64_t` (`GetSceneTexture`), so `Renderer.h` still doesn't mention Vulkan.

**Resizing:** when the Scene window changes size, `SetSceneTargetSize` asks for a new size, and the
next `BeginFrame` makes a new target. The old one may still be in use by a frame in flight, so it
isn't destroyed there. It's a `GpuResource` (`SceneTarget`: the two images plus ImGui's descriptor
set), parked in a frame's release list like any resource a game lets go of (M8), and destroyed
once that frame's fence says the GPU is done with it. So dragging a splitter never waits for the
GPU. In between, the old image is shown stretched for a frame.

**Hidden:** the editor calls `SetSceneTargetSize` every frame the Scene window is visible. In a frame
without the call (the Scene tab hidden behind another, or closed), the target is kept but nothing
is drawn into it. The games' path is unchanged: without a scene target, the scene and the UI share
the window's image.

### The editor camera isn't part of the scene

Unity's Scene view camera isn't a GameObject: it doesn't appear in the Hierarchy, isn't saved,
and the game never sees it. `EditorCamera` is the same: a position, a rotation and a lens, owned by
the editor.

- **Drawing from it:** each frame the scene submits its meshes and sets the renderer's camera from
  its main camera, as for a game. Then the new **`Application::OnRender`** hook runs, and the editor
  replaces the camera with its own (`SceneView::Render`). A game could use the same hook to draw
  from a second camera, or to submit extra meshes. The scene submits its meshes even when it has
  no camera, so the Scene view still shows a scene whose camera was deleted.
- **Flying:** `Fly(position, rotation, dt, settings)` is the code `FlyCamera` had, moved into a free
  function. `FlyCamera` passes its Transform's position and rotation, and its `Settings`; the
  editor camera passes its own. The axes it turns are `Transform::kForwardAxis`, `kUpAxis` and
  `kRightAxis`. `FlySettings::MoveOnlyWhileLooking` gives the Scene view's behavior: W/A/S/D move only
  while the right button is held, which leaves the keys free for shortcuts (M17's W/E/R).
- **Who gets the mouse:** while the pointer is over an ImGui window, ImGui wants the mouse, and the
  engine keeps presses from `Input` (M9). The Scene window is an ImGui window, but its picture
  belongs to the camera. So while the pointer is over the image (or the camera is flying), the
  Scene view calls `ImGui::SetNextFrameWantCaptureMouse(false)` (and the same for the keyboard),
  and `Input` sees the right button and the keys. During mouse look the cursor is locked, which
  turns ImGui's mouse handling off entirely (M9).

### Edit mode

`Application::SetSceneUpdating(false)` stops the scene's components from running: no `OnStart`,
`OnUpdate` or `OnFixedUpdate`. The scene is still drawn, and the editor still runs its own
`OnUpdate`. That's Unity's Edit mode, where a scene is data to arrange, not a game running. It
also keeps saves clean: a Spinner that ran while you edited would save its rotation at whatever
moment you pressed Ctrl+S. M18's Play button will turn updates on, on a copy of the scene.

### Docking

Dear ImGui's **docking build** lets windows be dragged into each other: as tabs, or side by side
with splitters between them, like Unity's panels.

- `DockSpaceOverViewport` makes the whole window, below the menu bar, a dock space.
- **The default layout** is built in code the first time (and on Window > Reset Layout) with
  ImGui's DockBuilder functions. They split the dock space into left (Hierarchy), right
  (Inspector), bottom (Project and Console as tabs) and center (Scene). They're in
  `imgui_internal.h`: ImGui's own API, public enough to use, but likelier to change between
  versions.
- **ImGui saves layouts as .ini text** (`SaveIniSettingsToMemory`), and can only apply a saved
  layout to windows it hasn't created yet. So the editor loads it once, before the first frame,
  and saves it when it quits. That's why the layout is the user's rather than each project's (Unity
  also keeps layouts per user).

### The Inspector: the third visitor

M13 introduced `FieldVisitor` so that a component lists its fields once: one visitor writes them
to a file, another reads them back. The Inspector is the third, as M13 promised.
`InspectorVisitor::Field` makes a widget per field:

| Field type | Widget |
|---|---|
| `float`, `vec2`, `vec3`, `vec4` | `DragFloat`, `DragFloat2/3/4` (drag, or Ctrl+click to type) |
| `vec3`/`vec4` named `...Color` | `ColorEdit3/4`: FieldVisitor knows types, not meaning, so the name decides |
| `quat` | three angles in degrees (Unity's Euler order: Z, then X, then Y) |
| mesh, texture | the asset name, read only |
| material | its settings, nested; a change asks `Assets` for the material with the new settings |

ImGui's widgets take a **pointer to the value** and change it in place when the user drags or types,
and return true in that frame. So the visitor edits the component's fields directly, and its
`Changed()` marks the scene unsaved.

- **Materials stay shared:** objects with equal settings share a material (M13), so editing one
  object's color can't recolor the material in place. That would recolor every object sharing it.
  Instead it gets the material with the new settings, which may be a new one. Unity has the same
  split: `sharedMaterial` vs `material`.
- **Lists** (a MeshRenderer's parts) are tree nodes. `FieldVisitor::List` visits every element even
  when a node is closed, so the visitor keeps a stack of "is this node open?" and draws nothing
  inside closed ones.
- **Labels** are nicified (`DegreesPerSecond` → "Degrees Per Second"), as Unity does.
- **IDs:** two components can both have a field called `Color`, and ImGui tells widgets apart by
  their labels, so each component pushes an ID scope.

### The Console: a listener, and a second thread

`Log::SetListener` hands every message to one listener, as well as printing it. The Console
registers itself in its constructor and unregisters in its destructor (RAII again). It's declared
first in `EditorApp`, so it's created before anything else and catches the startup messages too.

A message can be logged on any thread (Vulkan's validation callback, a file dialog's callback).
The listener only appends to an "incoming" list under a mutex. `Draw`, on the main thread, moves
the incoming messages into the list it draws, holding the lock only for that move. So drawing
needs no lock, and a message logged *during* drawing (an ImGui assert, say) can't deadlock.

The Console keeps up to 2000 messages, but draws only the lines that fit in its window:
`ImGuiListClipper` tells it which rows are visible, so a full log costs no more to draw than a
screenful.

### Asking before losing changes

Several actions leave the current scene: New Scene, Open Scene, Close Project, and closing the
window. Each goes through `AskToSaveThen(action)`:
- If nothing changed, it runs `action` right away.
- Otherwise it keeps `action` (a `std::function`) and shows the modal "Save them first?":
  - **Save** saves, then runs the action. A scene never saved first asks where, with the Save As
    dialog, and runs the action after that answer arrives.
  - **Don't Save** runs it.
  - **Cancel** drops it.

Closing the window uses the new **`Application::OnQuitRequested`**: returning false keeps the
editor running, and the prompt's action is `Quit()`. Unity's `Application.wantsToQuit` works the
same way. `Window::TakeCloseRequest` reports a close only once, so a cancelled close isn't asked
about again every frame.

## Reading guide

1. **`editor/src/EditorApp.cpp`**: `DrawEditor` (dock space, windows, F), `DrawMenuBar` and its
   shortcuts, then the scene actions (`NewScene`, `OpenScene`, `LoadScene`, `SaveScene`,
   `SaveSceneAs`, `AskToSaveThen`, `DrawSavePrompt`), `BuildDefaultLayout`, and the layout's load
   and save in `OnStart`/`OnShutdown`.
2. **`editor/src/SceneView.cpp`** and **`EditorCamera.cpp`**: the image, the input hand-over, and
   `Render`.
3. **`engine/src/Renderer/Renderer.cpp`**: `SceneTarget` and `RecreateSceneTarget` (deferred
   deletion again), then `EndFrame` (the two renderings and their barriers) and `RecordRendering`.
4. **`engine/src/Scene/FlyCamera.cpp`**: `Fly`, and `FlyCamera::OnUpdate` calling it.
5. **`editor/src/InspectorWindow.cpp`**: `InspectorVisitor`, then `DrawInspectorWindow`.
6. **`editor/src/HierarchyWindow.cpp`**, **`ProjectWindow.cpp`**, **`ConsoleWindow.cpp`**.
7. **`engine/include/Viva/Application.h`** (the new hooks) and **`engine/src/Core/Application.cpp`**
   (where they're called); **`engine/src/Core/Log.cpp`** (the listener);
   **`engine/src/Platform/FileDialog.cpp`** (three dialogs, one `ShowDialog`).

## How to test

1. **Open a project** in VivaEditor. A project with the demo assets shows the most (see M14's "How
   to test", step 8). The layout: Hierarchy left, Scene middle, Inspector right, Project and Console
   at the bottom. The Console has the startup log.
2. **Fly:** hold the right mouse button over the Scene and move the mouse; while holding it, W/A/S/D
   and Q/E fly, and Shift is faster. Without the button, the keys do nothing there.
3. **Select and inspect:** click Crate in the Hierarchy. The Inspector shows its Transform, Mesh
   Renderer (with the material inside) and Spinner. Drag Position's Y up: the crate rises. The
   title bar gets a `*`. Press **F**: the camera frames the crate.
4. **Materials:** change the crate's material Color, or its Tiling to 3, 3. The small crate, which
   used the same material, keeps the old look.
5. **Save:** Ctrl+S (or File > Save). The `*` goes; the Console says "Scene saved". The file in
   `Scenes/` has the new values.
6. **Unsaved prompt:** change something, then File > New Scene: the prompt appears. Try Cancel,
   then Don't Save. New Scene gives an "Untitled" scene with just a camera. Ctrl+S on it asks where
   to save (Save As).
7. **Open:** in the Project window, open `Scenes/` and double-click a `.scene`; or File > Open Scene.
8. **Layout:** drag a window's tab onto another window, or to an edge. Restart the editor: the
   layout is as you left it. Window > Reset Layout brings back the default.
9. **Quit with changes:** change something and close the window: the prompt appears.
10. **Edit mode:** the Spinners stand still. (They run in the Sandbox, and will in Play mode, M18.)

## Known limitations

- **No creating, deleting, renaming or reparenting** objects yet, no Add Component, and no mesh or
  texture pickers: that's M16. No clicking on objects in the Scene view either (M16), and no gizmos
  or undo (M17).
- **Euler angles in the Inspector** can jump when the X rotation passes ±90° (see the comment in
  `InspectorVisitor`). Unity avoids this by remembering the angles you typed.
- **Colors are recognized by name** (`...Color`).
- **F's framing distance** is a guess from the object's scale; M16 adds bounds.
- **The layout is per user, not per project** (see Docking).
- **The editor camera starts at the scene's main camera** each time a scene opens; it isn't
  remembered per scene.
- **One scene target:** the renderer can draw the scene into one image per frame, from one camera.
  M18's Game view (the scene through the game's camera, next to the Scene view) will need render
  targets as objects (Unity's RenderTexture), each with its own camera.
- **ImGui's shortcuts and text fields need keyboard focus**, which the automated tests don't take
  (see Verified on).
